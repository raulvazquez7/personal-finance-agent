# Agent wiki (OpenWiki) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate and commit a grounded OpenWiki agent wiki for this repo. The only change to
`CLAUDE.md` is OpenWiki's minimal `@AGENTS.md` block, and no file from `data/` or any secret is
ever read.

**Architecture:** OpenWiki `0.7.2`, run with `npx` from a fresh worktree of a new branch. The
worktree has no ignored files, and `.openwikiignore` is a second read boundary. A hand-written
brief (`openwiki/INSTRUCTIONS.md`) sets scope and the sources of truth. Generated pages are
never hand-edited: errors are fixed through the brief and a re-run.

**Tech Stack:** OpenWiki CLI 0.7.2 (Node ≥ 22.22.0; local Node is 26), one model provider
(Raul's choice, spec section 4), git, ripgrep.

**Spec:** `docs/superpowers/specs/2026-10-17-openwiki-design.md`

## Global Constraints

- Starts only after delivery 1 (`2026-10-17-public-face`) is merged into `main`.
- Raul's uncommitted `CLAUDE.md` edits in the main checkout are committed to `main` before Task 1.
  OpenWiki writes into `CLAUDE.md`, and the block must land on his current text.
- Never run OpenWiki in the main checkout: it holds `data/raw/`, `data/labels/` and `.env`.
- Provider keys live in `~/.openwiki/.env` or the shell environment, never in the repo, and are
  never printed.
- Pinned version: `npx -y openwiki@0.7.2`. Use a newer patch only if `npm view openwiki version`
  shows one, and record it in the PR.
- Do not edit generated files under `openwiki/` except `openwiki/INSTRUCTIONS.md`. At most two
  regeneration rounds after the first `--init`.
- Cost cap: 5 USD for the whole delivery unless Raul sets another. Stop and ask before exceeding it.
- English. Conventional commits. Do not push until Raul asks.

## Before Task 1 (controller, not a subagent)

1. Confirm that delivery 1 is merged and that `git -C <main checkout> status` shows no
   uncommitted `CLAUDE.md` change. If it shows one, stop and ask Raul to commit it.
2. Create the worktree:
   `git worktree add .superpowers/worktrees/docs-openwiki -b docs/openwiki origin/main`
   from the main checkout. All later commands run inside it.
3. Raul's provider decision (spec section 4). Record provider, model and cost cap in this
   plan's "Run record" at the bottom. Raul puts the key in `~/.openwiki/.env` himself, or
   the controller exports it into one shell from the main checkout's `.env` without echoing it
   (only for option C, `XAI_API_KEY`).
4. Look up the chosen provider's exact environment variables in the current docs
   (Context7 `/langchain-ai/openwiki`, page `concepts/model-providers`) and record them in the
   Run record. Do not guess the variable names.

## Review Focus

- **The read boundary leaks.** Expected: OpenWiki never lists or quotes `data/`, `.env`, spike
  outputs or `.claude/`. Task 1 asks it what it can see before any generation run.
- **`CLAUDE.md` gets more than the import.** Expected: the diff is exactly one marker-delimited
  block. Task 2 checks the diff line by line.
- **A generated page invents a feature,** such as a jev router, balances, chat evals or a
  deterministic answer check. Expected: caught and fixed through the brief. Task 3 reviews it.
- **Personal figures surface through the specs or the eval history.** Expected: only
  `HISTORY.md` metrics and test-fixture numbers appear. Task 3 lists every euro amount.
- **The update churns.** Expected: a second `--update` with no code change produces no diff.
  Task 3 runs it.

- [ ] **Step 2: Write `openwiki/INSTRUCTIONS.md`**

```markdown
# Brief for the tally ai repository wiki

## Audience

Coding agents changing this repository. Write practical, source-grounded pages: where things
live, why they are built that way, and how to verify a change. No marketing. People read the
README instead.

## Priorities, in order

1. A map of the code: the `apps/api/finance` packages (ingestion, categorization, dashboard,
   agent, evals, api), the `apps/web/src/app` routes, and `supabase/migrations`.
2. The categorization cascade: own-account pairing, system rules, jev (one call with three
   typed questions), merchant resolution, merchant defaults, the 0.95 review threshold, and
   `link_loans`.
3. The money rules. `docs/money-rules.md` is the contract: link it, do not restate it.
4. The chat agent: `create_agent` with the single `run_sql` tool, the `agent` schema and the
   `agent_reader` role, the sqlglot guard, the YAML semantic layer and its startup check, the
   checkpointer, and how to change a metric or an example safely.
5. How to verify a change: `uv run task test`, `task lint`, `task test-integration`, the
   scratch-database recipes R2 and R3, and agent-browser for UI flows.
6. The categorization eval: `finance eval-categorization`, and how to read
   `docs/evals/HISTORY.md` (the golden set changed between lines; noise is about ten rows).

## Sources of truth

- Code and tests win over every document.
- Specs in `docs/superpowers/specs/` explain why. The v1 spec's section 9 (a jev router in front
  of the chat) was superseded by the slice 4 spec's section 16: the shipped chat is one ReAct
  agent with no router.
- `docs/backlog.md` lists ideas that are not built. Never present one as existing.
- `CLAUDE.md` holds the working rules. Do not repeat them.

## Never

- Write personal amounts, account numbers, IBANs or merchant names from any source. Use only
  the metrics in `docs/evals/HISTORY.md` and numbers from test fixtures.
- Describe the contents of `data/` or of any ignored path.
- Copy the README or `docs/architecture.md`. Link them.
```

### Task 2: Generate the wiki

**Files:**
- Create (generated): `openwiki/**`, `openwiki/.claims/**`, `AGENTS.md`
- Modify (generated block only): `CLAUDE.md`

**Interfaces:**
- Consumes: `.openwikiignore` and `openwiki/INSTRUCTIONS.md` from Task 1, and the provider from
  the Run record.
- Produces: the committed wiki that Task 3 reviews.

- [ ] **Step 1: Run the first generation**

```bash
npx -y openwiki@0.7.2 code --init --print
```

Expected: it finishes and writes `openwiki/quickstart.md`, an index, pages and `.claims/`
sidecars. If it stops midway, re-run the same command: it resumes from `openwiki/.run.json`.
Record the reported usage or cost. If the projection exceeded the cap, stop and ask Raul.

- [ ] **Step 2: `CLAUDE.md` gained only the managed block**

```bash
git diff -U0 CLAUDE.md
```

Expected: only added lines, forming one block from `<!-- OPENWIKI:START -->` to
`<!-- OPENWIKI:END -->` that contains `@AGENTS.md`. No existing line changed. If anything else
changed, copy the managed block aside, run `git checkout -- CLAUDE.md`, re-insert only the block
(Edit tool) where OpenWiki put it, and report it.

- [ ] **Step 3: `AGENTS.md` is small and retrieval-first**

```bash
wc -l AGENTS.md && cat AGENTS.md
```

Expected:
- 40 lines or fewer;
- it tells agents not to preload or enumerate the wiki;
- it names `openwiki/quickstart.md` as the fallback.

If it is over 40 lines, stop and ask Raul whether to accept it. Claude Code loads it into every
session through the `@AGENTS.md` import.

- [ ] **Step 4: Privacy sweep**

```bash
rg -n 'ES[0-9]{22}' openwiki AGENTS.md || echo "no IBAN"
rg -n -i 'data/raw|data/labels' openwiki | rg -v -i 'ignored|git-ignored|never' || echo "no data paths described"
rg -n -o '[0-9][0-9.,]*[0-9] ?(€|EUR)|€ ?[0-9][0-9.,]*' openwiki | sort -u
```

Expected:
- `no IBAN`;
- `no data paths described`;
- a short list of euro amounts.

Every amount in that list must come from a test fixture or from `HISTORY.md`. Find each one in
the repo with `rg -n -F '<amount>' apps/api/tests docs/evals docs/money-rules.md`. An amount
you cannot find there is a finding for Task 3.

- [ ] **Step 5: Commit**

```bash
git add openwiki AGENTS.md CLAUDE.md
git commit -m "docs: generate the OpenWiki agent wiki"
```

### Task 3: Review, fix through the brief, prove stability

**Files:**
- Modify: `openwiki/INSTRUCTIONS.md` (only if the review finds errors)
- Regenerated: `openwiki/**`

**Interfaces:**
- Consumes: the wiki from Task 2.
- Produces: a reviewed wiki and a clean no-op update.

- [ ] **Step 1: Fact review (subagent)**

Dispatch a reviewer subagent. Do not pass a model override. Give it this brief:
- Read `openwiki/quickstart.md` and the pages covering categorization, the chat agent, the money
  rules, verification and evals.
- For each factual claim, check it against the code (and the sidecar in `openwiki/.claims/`
  where one exists).
- Return a table with three columns: claim, `file:line`, and verdict (`ok`, `wrong`,
  `untraceable`).
- Also return every euro amount with its source.
- Flag in particular:
  - any jev router presented as built;
  - account balances, chat evals or a deterministic answer check presented as built;
  - the threshold or merge values;
  - the wrong agent role or schema;
  - any instruction that contradicts `CLAUDE.md`.

- [ ] **Step 2: Fix through the brief (only if there are findings)**

For each `wrong` or `untraceable` claim, add one precise line to `openwiki/INSTRUCTIONS.md`
under "Sources of truth" or "Never" that would have prevented it. Then run:

```bash
npx -y openwiki@0.7.2 code --update --print
```

If `--update` leaves a page unchanged because no code changed, run `code --init --print` instead.
That is a full regeneration, so record its cost. At most two rounds. Errors left after two rounds
go into the PR description as known issues, with the reviewer's table.

- [ ] **Step 3: A second update is a no-op**

```bash
git add -A openwiki AGENTS.md CLAUDE.md && git commit -m "docs: correct the agent wiki through its brief" || true
npx -y openwiki@0.7.2 code --update --print
git status --porcelain -- openwiki AGENTS.md CLAUDE.md | rg -v 'openwiki/.last-update.json' || echo "no churn"
```

Expected: `no churn`. Only `.last-update.json` may change. Commit it if it did.

- [ ] **Step 4: Agent check (subagent)**

Dispatch a fresh subagent with no context about this work. Give it only this question:

> In this repository, where is the 0.95 review threshold applied and why that value? Report
> which files you read, in order.

Pass the worktree path. Expected: it reaches `AGENTS.md` and then `openwiki/quickstart.md` or a
specific wiki page, then the code, and answers correctly, without reading the whole `openwiki/`
tree. Record the answer and the files it read in the PR description.

- [ ] **Step 5: Commit any remaining change**

```bash
git add openwiki/.last-update.json && git commit -m "docs: record the OpenWiki update check" || true
```
